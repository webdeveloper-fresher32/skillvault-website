# Phase 12: Interview Process and Advanced Topics

This is the capstone phase. Phases 1–11 gave you the building blocks — OOP, SOLID, UML, design patterns, and full worked systems (parking lot, splitwise, booking systems, rate limiters, social feeds). This phase is about **performance under interview conditions**: how to structure your 45 minutes, how to think out loud, and how to handle both easy warm-up prompts and staff-level "design something huge" prompts.

## What's in This Phase

| File | Focus |
|------|-------|
| `01-How-to-Solve-an-LLD-Interview.md` | The repeatable 7-step framework for solving *any* LLD prompt live, worked end-to-end on Tic-Tac-Toe |
| `02-Object-Identification-Practice-Drills.md` | Fast drilling reps on classic warm-up prompts: Chess, Snake & Ladder, Tic-Tac-Toe deep dive, Vending Machine, Calculator |
| `03-Advanced-System-Designs-Discussion.md` | Discussion-level treatment of staff-tier prompts: Google Docs, Netflix/YouTube, Jira, GitHub, Slack/Discord |

## Goals

By the end of this phase you should be able to:

- Run a structured clarification phase in under 3–4 minutes instead of jumping straight to code.
- Extract entities and relationships from a plain-English prompt reliably, every time.
- Map common "symptoms" in a requirement to the right design pattern without hesitating.
- Proactively narrate extensibility ("if requirement X changed, I'd change Y") without being asked.
- Recognize when a prompt is intentionally too large for full code, and know what the interviewer is actually scoring in that case (breadth, trade-offs, prioritization) rather than trying to write everything.

## How to Use This Phase

Read `01` once fully — it's the framework you'll reuse in every interview. Then use `02` as flashcard-style repetition: cover the code skeleton, try to reconstruct the class list and key decision from memory, then check yourself. Read `03` last, as a discussion primer — you are not expected to write full code for these, only to hold your own in a verbal design conversation.
