> This phase teaches you how to model data the MongoDB way — not the SQL way.

## 1. Phase Objectives

By the end of Phase 03 you will be able to:

- [ ] Describe the difference between schema-on-read and schema-on-write
- [ ] Explain ObjectId anatomy and why it is globally unique without coordination
- [ ] Apply the 8 canonical MongoDB schema design patterns to real problems
- [ ] Model One-to-One, One-to-Many, and Many-to-Many relationships in MongoDB
- [ ] Decide when to embed a subdocument vs when to reference another collection
- [ ] Identify and fix common schema anti-patterns (unbounded arrays, massive documents)
- [ ] Use `$lookup` to perform joins across collections when referencing
- [ ] Design a schema that supports your application's most frequent query patterns
- [ ] Understand capped collections and their use cases (audit logs, event streams)
- [ ] Enforce optional validation rules using JSON Schema validators

**These objectives map to the "Data Modeling" and "Schema Design" domains of the MongoDB C100DEV and C100DBA exams.**

## 5. Key Concepts at a Glance

```text
┌────────────────────┬─────────────────────────────────────────────────┐
│ Concept            │ One-Line Summary                                │
├────────────────────┼─────────────────────────────────────────────────┤
│ Document           │ A JSON-like object; the basic unit of storage   │
│ Collection         │ A group of documents (like a table, but loose)  │
│ ObjectId           │ 12-byte globally unique _id generated by driver │
│ Flexible Schema    │ Documents in the same collection can differ     │
│ Schema-on-Read     │ Shape enforced by the app, not the database     │
│ Embedding          │ Store related data inside the parent document   │
│ Referencing        │ Store a foreign key; use $lookup to join        │
│ Capped Collection  │ Fixed-size ring buffer; oldest docs auto-expire │
│ Polymorphic        │ One collection, documents of different shapes   │
│ Bucket Pattern     │ Group time-series rows into one document/bucket │
└────────────────────┴─────────────────────────────────────────────────┘
```

## 6. Hands-On Exercises

Work through these after reading all three files in order:

1. **Design a blog schema** — users, posts, comments. Choose embed vs reference for each relationship and justify your choice in comments.
2. **Model IoT sensor data** — a temperature sensor sends a reading every second. Design a schema that avoids creating millions of tiny documents. (Hint: Bucket Pattern.)
3. **Apply the Subset Pattern** — a product has 500 reviews. Design a schema where the product document only stores the 5 most recent reviews; the rest live in a separate collection.
4. **Spot the anti-patterns** — given a schema with unbounded arrays and a 20MB document, rewrite it correctly.
5. **Schema versioning** — an existing `orders` collection has 2 million documents. A new field `taxRate` needs to be added. Design a migration strategy using the Schema Versioning Pattern.
